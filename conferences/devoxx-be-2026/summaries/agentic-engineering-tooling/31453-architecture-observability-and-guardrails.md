# Architecture Observability and Guardrails

Victor Rentea · Conference · Agentic Engineering & Tooling

## TL;DR

AI agents now submit thousand-line pull requests no human can seriously review, so Rentea built an open-source "guided human review" page per PR that makes the change observable: narrated demo videos, API diffs, generated architecture diagrams, semantic test coverage, and runtime sequence diagrams captured from tests. The talk is a live tour of that tool over a Spring PetClinic PR, arguing every guardrail should be a deterministic script with zero drift rather than an AI opinion. It closes with a plea to open-source users: file good issues instead of AI-shoveled pull requests.

## Key takeaways

- Always review agent-written code with a smarter agent (or higher effort) than the one that wrote it: few output tokens make it pure economy.
- Let the coding agent refuse to fix review findings it judges to be nits, and keep the refused list visible so a human can overrule it.
- Never summon the human reviewer until the branch has zero drift from main; the code should be impeccable before it asks for attention.
- Generate review diagrams with deterministic scripts (reflection scans, trace converters), never by asking AI to draw a picture: zero tokens, zero hallucination, reproducible forever.
- Trust acceptance and end-to-end tests over AI-generated unit tests, and always read the glue code underneath generated tests.
- Correlate bug-fix history (Jira tags in PR titles) with code metrics to see where the business keeps paying for the same files.

## Notes

### [01:36](https://youtu.be/BOcNjR2lBus?t=96) Zero slides, two repos, one review page

Rentea opens with no slides: the whole talk is a live demo of a per-PR review page served by a Python server he vibe-coded without reading ("I just exerted will"), backed by two open-source GitHub repositories under the Unlicense, with feedback requested as issues. The page recaps the previous day's talk: a confused human facing a 10,000-line PR gets a guide built from implementation assumptions, adversarial review findings, and autofixes. A follow-up frustrated-user meetup is announced for October 13.

### [04:43](https://youtu.be/BOcNjR2lBus?t=283) The guided review: assumptions, findings, costs

PR #51 ("Owners grid: paged and sorted by Name or City", implementing issue #25) shows 4 implementation assumptions, 14 open review issues, and 25 auto-fixed findings, all published on GitHub. Every stage carries its price: implementation $15, a quorum of five adversarial reviewers $5, autofixes $9, the guide itself $0.30, $32 total. Test churn reads +42/−12/5 edited. The branch sits 5 commits behind main, which blocks the human summons. A VS Code extension highlights commented lines and jumps from the page into the editor; a GitHub app lets the reviewer argue with the agent inline.

### [16:07](https://youtu.be/BOcNjR2lBus?t=967) Demo and API tabs

The Demo tab plays narrated video walkthroughs of the new feature with YouTube-style chapters, generated from a prompt polished for three hours. The API tab diffs the OpenAPI spec and flags one breaking change via oasdiff, warning that a single shared DTO referenced by several endpoints breaks them all at once, and suggests building the same check on AsyncAPI for Kafka and RabbitMQ messages.

### [20:46](https://youtu.be/BOcNjR2lBus?t=1246) Data tab: diagrams generated from code, then unit-tested

The domain-model PlantUML is generated by Java reflection scanning, and the schema PlantUML from migrations run against an empty Testcontainers database: no AI, no tokens, no drift. A new-vs-old diff colors added elements green, but any added line re-lays-out the whole PlantUML drawing and destroys the reviewer's geographic memory. The fix: keep hand-drawn Draw.io diagrams (whose PNGs embed editable XML) and unit-test them against reality; when the test fails, AI adds the missing edge in red, the human re-lays-out the diagram by hand, resets colors, deletes the label, and rebuilds the report.

### [27:36](https://youtu.be/BOcNjR2lBus?t=1656) Tests tab: which test covers which requirement

Each of the 345 tests ran alone under a coverage probe, so the page lists exactly the tests that executed any of the ~500 changed lines, then uses AI to match semantic coverage of tests against the Jira/GitHub issue and calls out uncovered requirements. Clicking navigates both ways between requirement and covering test. Unit tests that map to no requirement are distrusted; the acceptance tests that hit the UI matter most, and generated tests demand a look at the glue code underneath. Playwright's trace viewer shows network fetches captured during the UI test run.

### [33:26](https://youtu.be/BOcNjR2lBus?t=2006) Sequence tab: OpenTelemetry traces become sequence diagrams

End-to-end tests push traces with 100% sampling into Grafana: a test annotation initiates the trace, propagates it over HTTP into the REST API, and a TypeScript tag plus browser instrumentation captures the frontend, all via the zero-instrumentation OpenTelemetry agent. A short script converts each trace into a PlantUML sequence diagram showing browser, backend, SQL with bound parameters, and cross-service calls (NotificationService, SMS gateway) with request and response payloads. On screen, an N+1 Hibernate query problem is visible in plain sight in a captured sequence. JVM arguments extend the same interception to calls crossing Maven module boundaries in a modular monolith with zero lines of code, and `@WithSpan` covers even private methods. ArchUnit checks classes against PlantUML, and a C4 C2 diagram is generated from calls that actually happened at runtime.

### [42:54](https://youtu.be/BOcNjR2lBus?t=2574) Code city, metrics, and the closing plea

A Code City view maps file size to block area, if-statement count to height, and acceptance coverage to color, with growth arrows from the PR; Rentea flies through the JDK's String class and the whole Spring Framework. Behind it sit per-file metrics: commits, bug-fix commits correlated with Jira tags, number of authors, instability, incoming and outgoing coupling, line versus acceptance coverage, CRAP, and cohesion (packages that change together). Remaining tabs get a rushed pass: pixel-perfect visual regression and combo-box smell detection, a method-invocation complexity graph built with JavaParser and IntelliJ structural search, and CODEOWNERS routing where touching contracts summons tech leads and touching guardrail files summons "the lord". The close asks the audience to stop submitting AI-generated pull requests to open source and file issues instead, then pitches stickers, token discipline (Uber burned a yearly budget in four months), and the agentic.how masterclass.

## Tools, libraries and specs

- OpenTelemetry (zero-instrumentation Java agent, browser instrumentation, `@WithSpan`)
- Grafana (trace collection from end-to-end tests, 100% sampling)
- PlantUML (reflection- and trace-generated diagrams)
- Draw.io (PNG-embedded diagrams unit-tested against the code)
- oasdiff (OpenAPI breaking-change detection)
- AsyncAPI (proposed message-contract equivalent)
- ArchUnit (class-to-diagram checks)
- Playwright trace viewer (network capture from UI tests)
- Testcontainers (empty-database migration runs for schema diagrams)
- JavaParser, IntelliJ structural search (method-invocation graph)
- C4 model (C2 container diagrams from runtime calls)
- Code City (size/complexity/coverage visualization)
- Spring Framework, Hibernate (demo targets; N+1 query capture)
- VS Code extension + Python server (the review tool itself)

## Who should watch

Engineers drowning in large AI-generated pull requests, and anyone building review tooling or architecture fitness functions, will get the most from it. Teams without end-to-end tests or trace infrastructure can skip the middle third until they have something to observe. Viewers wanting a calm, prepared narrative should look elsewhere: this is a deliberately chaotic live demo that runs out of time.

## Verdict

**7/10**: A live, end-to-end tour of an original per-PR review tool with a public demo, held back by credited and off-the-shelf parts inside the speaker's own tool, self-reported totals, and a core capture pipeline whose wiring is skipped.

**Reach segment**: JVM teams already reviewing large AI-written pull requests who have end-to-end tests and can add OpenTelemetry, since the Sequence, City and architecture-check tabs depend on that setup.

**Novelty 1/2**

- **+** [25:30](https://youtu.be/BOcNjR2lBus?t=1530) Unit-testing hand-drawn Draw.io diagrams against the code, with AI adding the missing edge in red for a human to lay out, is a technique of the speaker's own design.
- **+** [28:08](https://youtu.be/BOcNjR2lBus?t=1688) Listing the tests that executed any of the ~500 changed lines and AI-matching them to the issue is the speaker's own pipeline.
- **·** [42:54](https://youtu.be/BOcNjR2lBus?t=2574) Code City ("Very old idea") and the trace-to-PlantUML script from "a friend of mine" ([35:00](https://youtu.be/BOcNjR2lBus?t=2100)) are credited ingredients, and oasdiff, OpenTelemetry and PlantUML are off-the-shelf, so the page is an assembly inside the speaker's own tool, which rates 1.

**Demonstrated 2/2**

- **+** [04:43](https://youtu.be/BOcNjR2lBus?t=283) The review page for PR #51 renders live with its assumptions, open findings and auto-fixed items, and the Demo, API, Data, Tests, Sequence and City tabs are clicked through on screen.
- **+** [36:34](https://youtu.be/BOcNjR2lBus?t=2194) The N+1 query problem appears live inside a captured sequence with the actual SQL and bound values visible.
- **−** [37:39](https://youtu.be/BOcNjR2lBus?t=2259) Peripheral pieces fail or are cut: one endpoint's response payload does not render ("that didn't work right now"), the module-callback detail needs repeated clicks at [39:16](https://youtu.be/BOcNjR2lBus?t=2356), and the Codeowners tab is dropped at [48:36](https://youtu.be/BOcNjR2lBus?t=2916), while the PR #51 run itself works.

**Measured 1/2**

- **+** [07:18](https://youtu.be/BOcNjR2lBus?t=438) Every pipeline stage carries a stated dollar cost ($15 implementation, $5 review quorum, $9 autofixes), grounding the economics argument.
- **·** [19:12](https://youtu.be/BOcNjR2lBus?t=1152) PR totals (lines +1590/−380, tests +42/−12/5, 25 fixed) are self-reported counts with no baseline or method, so they illustrate scale rather than prove effect.

**Depth 1/2**

- **+** [42:23](https://youtu.be/BOcNjR2lBus?t=2543) The zero-drift principle is argued with reasons: ask AI to write the diagram-generating script once instead of asking it for opinions on every run.
- **+** [24:25](https://youtu.be/BOcNjR2lBus?t=1465) The trade-off behind hand-drawn diagrams is explained: one added line re-lays-out a PlantUML drawing and destroys the reviewer's "geographic memory".
- **−** [35:30](https://youtu.be/BOcNjR2lBus?t=2130) How the trace capture was wired is waved away ("it plugged in the open telemetry … zero instrumentation agent … I don't care. done"), so the core pipeline is shown but its wiring goes unexplained.

**Reusable 2/2**

- **+** [09:54](https://youtu.be/BOcNjR2lBus?t=594) A demo of the review page is published online and browsable from a phone via the shown QR code, which reproduces the talk's main content.
- **·** [01:36](https://youtu.be/BOcNjR2lBus?t=96) Two open-source GitHub repositories hold the review tool itself, with issues invited as the feedback channel; as the project's own repositories they alone would rate 1.
